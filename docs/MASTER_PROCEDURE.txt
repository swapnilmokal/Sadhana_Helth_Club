साधना हेल्थ अँड न्यूट्रिशन सेंटर (SADHANA HEALTH & NUTRITION CENTER) PWA — MASTER FUNCTION & PROCEDURE MAP

1. PURPOSE
Two installable PWAs: USER APP for each center member and ADMIN APP for the center owners (wellness coaches Bhagwan Mokal and Sadhana Mokal). Track Day-1 baseline, daily health/wellness logs, activities, goals, progress charts, before/after photos, health updates, calendar, appointments, notifications, attendance and combined center analytics.

2. USER APP
Login/Register; Consent; Home Dashboard; Profile; Day-1 Baseline; Daily Health Update; Body Measurements; Activity/Steps/Water/Sleep; Goals; Progress Charts; Before/After Photos; Health Updates; Calendar; Appointments; Notifications; Attendance; About & Contact; Privacy; Logout.

3. ADMIN APP
Secure Login; Combined Dashboard; Member Management; Full Member Profile; Health Monitoring; Daily Progress; Activity; Before/After Photos; Health Updates; Calendar/Appointments; Notifications; Attendance; Reports; Goals/Follow-ups; Staff Roles; Audit Log; About & Contact; Settings; Export/Backup.

4. DAY-1 FLOW
Register -> consent -> admin verifies -> baseline assessment -> height/weight/BMI/BP/sugar/pulse/waist/hip and configured fields -> save MEMBER_HEALTH_PROFILE -> save first DAILY_HEALTH_LOG -> set goals -> start timeline.

5. DAILY FLOW
User opens Daily Update -> enters permitted measurements/activity -> client validation -> server validation -> append DAILY_HEALTH_LOG -> refresh user dashboard -> flag/update admin dashboard. Never overwrite historical records.

6. BMI
BMI = kg / (metres x metres). Use only as a tracking metric and do not infer diagnosis from it.

7. BEFORE/AFTER
Select BEFORE/AFTER, view (front/side/back), date, caption and consent -> upload to private storage -> save reference in BEFORE_AFTER_PHOTOS -> show only to authorized user/admin -> support consent revocation/deletion.

8. HEALTH UPDATE
User can add personal wellness/activity update. Admin can add follow-up note. Store author/date/time. Avoid unrestricted public display of sensitive data.

9. PROGRESS
Day 1 baseline -> daily logs -> weekly/monthly summaries -> goals -> trend charts -> photo timeline -> follow-up reminders.

10. ADMIN COMBINED DATA
Total members, active members, visits today, updates today, appointments, pending follow-ups, tracking coverage, activity coverage, goal progress and configurable aggregate trends. Filters by date/member/status/group.

11. CALENDAR
Center visit, measurement day, appointment, progress review, reminder and center event. User sees own events; admin sees authorized center events.

12. NOTIFICATIONS
Daily update reminder, appointment reminder, missed update, progress review, admin announcement, goal milestone and follow-up. Store status/readAt.

13. ATTENDANCE
User check-in or admin mark -> date/check-in/check-out/status/actor -> admin daily/monthly report -> corrections audited.

14. GOOGLE SHEETS
Recommended tabs: CONFIG, ADMINS, MEMBERS, MEMBER_HEALTH_PROFILE, DAILY_HEALTH_LOG, BODY_MEASUREMENTS, GOALS, PROGRESS_LOG, BEFORE_AFTER_PHOTOS, HEALTH_UPDATES, ACTIVITY_LOG, APPOINTMENTS, CALENDAR, NOTIFICATIONS, ATTENDANCE, MEMBER_NOTES, PRODUCTS, ORDERS, ORDER_ITEMS, PAYMENTS, AUDIT_LOG, SETTINGS.

15. API
GET: config, members, member, dailyLogs, healthUpdates, appointments, notifications, adminDashboard. POST: login, register, createMember, updateMember, createDailyHealthLog, createHealthUpdate, createActivity, createAppointment, cancelAppointment, uploadPhoto, createGoal, markNotificationRead, attendance, adminNote.

16. SECURITY
Server-side authentication/authorization; never trust browser role; no credentials in GitHub; HTTPS; private Sheet/photo storage; minimum necessary data; audit log; consent; retention/deletion; backup. User can see only own data; admin can see authorized members.

17. PWA
manifest + service worker; mobile-first; installable; cache app shell only; do not blindly cache private API responses.

25. SERVER MODE (v2): LOGIN, SYNC, STORAGE, BACKUP
- Login: member = own mobile number + PIN; admin = admin mobile + PIN. PIN is stored only as a salted hash on the server. 5 wrong tries lock the account for 15 minutes.
- PIN: member/admin can change their own PIN; admin can reset a member's PIN (temporary PIN, member must set a new one); a PIN reset or status change to Inactive logs the person out on all devices.
- Admin can edit all member details (name, login mobile, DOB, gender, address, emergency contact, status, height, goal); members can edit their own profile and goal. Health history is append-only (never overwritten).
- Sync: every change is queued on the phone and sent to the server; each app pulls other people's changes (every 30 s, on opening, on reconnect). Members only ever receive their own data; admin notes and audit log are admin-only.
- Phone storage: data and the sync queue are kept in IndexedDB (persistent storage is requested); the app works offline and syncs later. Logging out wipes the phone copy.
- Photos: uploaded to a private Google Drive folder; only the owner and admin can read them; deleting a photo trashes the Drive file.
- Backup: automatic daily copy of the Google Sheet to Drive folder Sadhana_Backups (last 30 kept), on-demand server backup, and a JSON download (with photos) from the Admin app.
- Setup steps: docs/SETUP_MARATHI.md.
